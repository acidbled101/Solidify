SLIDE 2 — THE POST-PROCESSING LADDER
==============================================================================

Principle: start at the highest-quality method. Fall one rung only when the
rung above fails. Stop as soon as the mesh is acceptable. The UI tells the user
live which rung it is on, why the previous one was abandoned, and the cost.

Source: trellis_core/printprep/printable_v2.py  (rung messages are verbatim)

RUNG 1 — Manifold3D accepts the mesh as-is
    COST: nothing
    ALGORITHM: exact-predicate validation of an oriented 2-manifold. Every edge
    must be shared by exactly two faces with coherent winding. If it passes, no
    geometry is touched at all.

RUNG 2 — PyMeshLab repairs non-manifold edges and vertices
    COST: nothing — the model keeps its own triangles
    ALGORITHM: topological splitting of non-manifold edges and vertices, then
    hole-filling on boundary loops up to 1000 edges. Connectivity is edited;
    vertex positions are not.

RUNG 3 — Fan-patch the remaining small boundary loops
    COST: nothing — only adds triangles across holes
    ALGORITHM: a triangle fan from a centroid vertex across each small boundary
    loop PyMeshLab declined. PyMeshLab refuses any hole touching a non-manifold
    vertex, which is exactly the set this rung picks up.

RUNG 4 — MeshLib signed-distance-field rebuild
    COST: the surface is resampled from here on, so the finest detail is lost
    ALGORITHM: ray-parity orientation repair (findDisorientedFaces) to fix
    scrambled face winding, then a signed distance field with hole-tolerant
    winding-number sign detection, extracted by dual marching cubes. Sub-voxel
    accurate, so it is closer to the original surface than a binary voxel grid.
    NOTE: this rung branches. If MeshLib is unavailable it falls through
    directly to the v1 voxel remesh instead.

RUNG 5 — Binary voxel remesh
    COST: coarsest path — the model is rebuilt from a voxel grid, UVs are gone
    ALGORITHM: voxelize to a dense occupancy grid, flood-fill the exterior,
    extract the isosurface with marching cubes. Cannot produce an open surface,
    so it always succeeds — which is why it is the floor of the ladder.
    Triggered when the SDF rebuild came back manifold but still OPEN, which
    Manifold3D will not accept.

OBSERVED LADDER PATHS (real runs, this machine)
    3DBenchy : rung 2 -> 3 -> 4 -> 5      ended watertight
    Toad     : rung 2 -> 3 -> 4           ended watertight
    Both also: filled enclosed cavities (16 and 23 respectively), and nudged
    vertices apart to survive the float32 STL round-trip (1 and 6).

SLIDE 4 — THE FLOW MODEL
==============================================================================

A flow model learns a VELOCITY FIELD, not a denoiser. It learns the straight-
line velocity that carries pure noise onto the data distribution, then
integrates it. 12 Euler steps is enough in this pipeline.

  interpolation path      x_t = (1 - t)*x_0 + (sigma_min + (1-sigma_min)*t)*eps
  velocity target         v   = (1 - sigma_min)*eps - x_0
  network                 v_theta(x_t, t, image_conditioning) -> dx/dt
  sigma_min               1e-5   (must equal the sampler's own value)
  timestep sampling       logit-normal (rectified-flow standard), clamped t_max = 0.99

  DIAGRAM: noise cloud on the left (x_0 ~ N(0,I)), geometry cloud on the right
  (x_1 = structured latent), near-straight trajectories between them with
  arrowheads, a timeline t = 0 -> 0.5 -> 1 underneath.

WHY IT MATTERS FOR THIS PROJECT: the training target is a plain regression onto
a velocity. That is what makes fine-tuning it cheap enough to do on a Mac.

SLIDE 5 — DPO / INFERENCE-TIME PREFERENCE STEERING (explored, retired)
==============================================================================

IDEA: run the ordinary sampler to a branch timestep t_branch in [0.3, 0.7],
fork two candidate trajectories, decode both to meshes, score them with a
physics-aware judge, and use the preference to steer the trajectory. Then
resume sampling. No weight updates, no preference dataset, no training.

THE JUDGE (trellis_core -> evaluation/geometric_judge.py)
    S = alpha*R_detail - beta*L_overhang - gamma*L_thickness - delta*L_topology

    R_detail     surface energy — rewards retained detail
    L_overhang   fraction of surface steeper than 45 deg from vertical
    L_thickness  walls thinner than d_min (0.02), sampled by ray casting
    L_topology   non-manifold edges, open edges, loose components

WHY IT IS ATTRACTIVE
    - no training run, no GPU-days, no preference dataset to collect
    - the judge is physics, measured directly on the decoded mesh — not a
      learned reward model that can be gamed

WHY IT WAS RETIRED
    - ONE RUN TAKES OVER 40 MINUTES ON THE MAC. Every candidate has to be
      decoded to a full mesh before it can be judged, and decoding dominates.
    - the theory holds and is worth revisiting on hardware this lab does not
      have. It was replaced by weight-space LoRA fine-tuning, which pays the
      cost once at training time instead of on every single generation.

SCALE OF WHAT WAS BUILT (kept in the repo, clearly marked as concluded)
    ~6,000 lines, 60 passing tests, 22 recorded runs with full traces
    experiments/dpo_inference_steering/

Verified by loading adapters/sft-1200-1050.pt directly.

  rank r                     16
  alpha                      32
  scaling                    alpha/r = 2.0
  TRAINABLE PARAMETERS       18,677,760   (18.68 M)
  adapter tensors            420
  WRAPPED MODULES            210
  FROZEN BASE PARAMETERS     1.29 B
  share of model training    1.4 %
  adapter file size          75 MB (optimizer state stripped)

  FORMULA          h = W x + (alpha/r) * B A x
  W                frozen, 1536 x 1536
  A                1536 x 16     (also 1024 x 16 and 8192 x 16 variants)
  B                16 x 1536,  INITIALISED TO ZERO

  B starting at zero means day-one output is IDENTICAL to the base model, and
  disabling the adapter afterwards is bit-exact — "base" really is base.

  WHICH MODULES (210 total, across 30 transformer blocks)
      to_qkv    30     self-attention fused q,k,v projection
      to_q      30     cross-attention query
      to_kv     30     cross-attention key/value
      to_out    60     attention output projections
      mlp.0     30     MLP in-projection
      mlp.2     30     MLP out-projection

  WHY LoRA AT ALL: a full fine-tune needs gradients plus Adam moments for all
  1.29 B parameters — roughly 15 GB of optimizer state alone, on top of
  activations, against a 36 GB unified-memory ceiling shared with the OS.

SLIDE 8 — RESULTS: PRINTABILITY vs STOCK TRELLIS.2
==============================================================================

Source: runs/comparison_900/results.json  and  INDEX.md
Method: same photographs, same seeds. The sparse structure is sampled ONCE per
photo and reused by every model, and the SLat noise is seeded per photo, so the
comparison is paired by construction — the only thing changing is the weights.
RAW MODEL OUTPUT. No repair, no decimation.

  model                                  non-manifold%   open%   components   detail
  stock TRELLIS.2 (no training)              0.923       0.984      6,301      0.772
  fine-tuned  sft-1200 @1050                 0.515       0.835      3,800      0.784
  fine-tuned  sft-900  @5220                 0.610       0.793      4,362      0.782

  HEADLINE (sft-1200 @1050 vs stock)
      non-manifold edges     0.923% -> 0.515%      -44%
      loose components       6,301  -> 3,800       -40%
      surface detail         0.772  -> 0.784       unchanged (slightly up)

  The detail number matters: the gain is NOT bought by smoothing the mesh into
  a blob. If detail had dropped, the improvement would be worthless.

  WHAT THE METRICS MEAN
      non-manifold edge   an edge shared by three or more faces. A slicer
                          cannot decide inside from outside and rejects it.
      open edge           an edge belonging to only one face — a hole.
      components          disconnected shells floating inside or beside the
                          model.
      detail              surface energy; a proxy for retained fine geometry.

*** MEASUREMENT WARNING ***
  Measure GEOMETRY-ONLY output. The same toad mesh measured after the texture
  bake reports 46.767% open edges and 68,376 components, because xatlas splits
  vertices along every UV seam — connectivity is shredded while the shape is
  untouched. That is a 58x difference from a step that changes nothing.
  Use  generate.py --no-texture  (the server already defaults to this).

TWO ENGINEERING FINDINGS WORTH A SENTENCE IF ASKED
    1. NaN gradients pass a threshold check. The spike-skip guard read
       `grad_norm > threshold * median`, and every comparison against NaN is
       False — so NaN gradients went straight into AdamW and an 18-hour run
       trained on poisoned weights, silently. Fixed by testing finiteness
       FIRST. It fired 16 times in the successful rerun.
    2. Mini-batching corrupts the loss by 6.5% on non-flash-attention backends,
       because padding mixed-length objects without an attention mask lets the
       padding participate. Caught by a correctness gate BEFORE it could damage
       a run; the CUDA trainer now refuses --max-batch > 1 unless the backend
       is flash_attn.
